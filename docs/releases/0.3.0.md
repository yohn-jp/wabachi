# Wabachi 0.3.0

## Summary

0.3.0 adds a Candidate Working Set artifact derived from evidence, migrates
Architecture diagram rendering to React Flow, and extends Architecture Canon
diagnostics and dogfood certification. It is a minor release: no intended
breaking changes to existing `run`, `matrix`, `architecture validate`, or
`architecture render` semantics.

## Added

- Candidate Working Set artifact, with bounded working-set seeds and
  evidence-derived working sets.
- Working-set conflict and provenance diagnostics.
- Working-set quality measurement harness.
- Deterministic React Flow + ELK projection for Architecture diagrams,
  including static HTML rendering.
- Minimal Architecture Canon authoring discovery.
- Bounded external-process stderr diagnostics surfaced during execution.
- Architecture validation summary counts.

## Changed

- Architecture diagram rendering migrated to React Flow.
- Architecture Canon adopted the conventional Wabachi Canon location.
- Dogfood Canon aligned with production architecture, and its certification
  trigger follows conventional Canon dogfood conventions.
- Matrix revision requirements are now discoverable.
- Missing Architecture Canon diagnostics are normalized instead of surfacing
  as unhandled gaps.

## Fixed

- `git archive | tar` pipe now uses `spawn` instead of `execFile`.
- Architecture diagram rendering issues under React Flow.

## Compatibility

There are no intended breaking changes in 0.3.0.

Existing `run`, `matrix`, `architecture validate`, and `architecture render`
execution semantics remain compatible with 0.2.1. Node.js 24 or newer remains
required.

## Upgrade

```bash
npm install --global wabachi@0.3.0
wabachi --version
wabachi --help
wabachi skill
```

Expected version output:

```text
0.3.0
```

## Release verification

Before creating the GitHub Release, the exact release merge commit must have
a successful `Architecture dogfood certification` workflow run.

Publishing is triggered by GitHub Release `v0.3.0` and uses npm Trusted
Publishing through the repository's release-triggered publish workflow. The
workflow rebuilds, tests, packs one tarball, verifies the release source and
exact-source dogfood certification, smoke-tests the same tarball, and
publishes those bytes to npm.
