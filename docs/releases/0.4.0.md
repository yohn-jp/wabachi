# Wabachi 0.4.0

## Summary

0.4.0 evolves the existing Architecture Canon into a lifecycle-managed Design
Intent authority (Epic #188). It adds deterministic Design Change Sets over
the current Canon, an XState-governed review/approval/implementation/
certification/promotion lifecycle, repository-resident persistence for
current/proposed/lifecycle/evidence state, source-level Code Intent, and a
bounded `wabachi design` CLI surface. It is a minor release: no intended
breaking changes to existing `run`, `matrix`, `architecture validate`, or
`architecture render` semantics.

## Added

- Design Change Set semantics over the existing Architecture Canon, with a
  deterministic codec and semantic diff.
- XState-backed Design Change lifecycle machine covering draft, review,
  approval, implementation, certification, promotion, and rework/rejection
  paths.
- Repository-resident persistence for Design Change, review, and lifecycle
  event state, including crash-safe filesystem transactions and a byte CAS.
- Design review freshness and rework semantics as a first-class
  pre-implementation gate.
- External Inari Implementation linkage codec for approved Design Changes,
  without transferring Inari authorization authority.
- Post-implementation certification: repository evidence admission, machine
  checks, canonical certification freshness bindings, and Code Intent
  obligation-target acceptance.
- Certified promotion of an approved Design Change into the current
  Architecture Canon, including current/proposed graph delta projection.
- Source-level Code Intent modeled inside the existing Canon authority, with
  canonical Code Intent Design Change operations.
- `wabachi design` CLI: `create`, `amend`, `submit`, `review`, `start`,
  `rework`, `link`, `certify`, `promote`, `recover`, and `render`.
- Production dogfood of the complete Design lifecycle through certification
  and promotion on Wabachi's own Canon.

## Changed

- Architecture Canon extended to carry Design Intent lifecycle state
  alongside existing current-Canon semantics.
- Design mutations route through canonical producers instead of ad hoc
  application code.

## Fixed

- Design review and lifecycle state now persist atomically.
- TOCTOU races closed in stored artifact and lock-owner reads.
- Recovery lock takeover is single-winner.
- Qualified provider symbol evidence matching corrected for certification.
- CLI result serialization preserved on successful Design commands.

## Compatibility

There are no intended breaking changes in 0.4.0.

Existing `run`, `matrix`, `architecture validate`, and `architecture render`
execution semantics remain compatible with 0.3.0. Node.js 24 or newer remains
required. XState is now a runtime dependency.

## Upgrade

```bash
npm install --global wabachi@0.4.0
wabachi --version
wabachi --help
wabachi skill
```

Expected version output:

```text
0.4.0
```

## Release verification

Before creating the GitHub Release, the exact release merge commit must have
a successful `Architecture dogfood certification` workflow run.

Publishing is triggered by GitHub Release `v0.4.0` and uses npm Trusted
Publishing through the repository's release-triggered publish workflow. The
workflow rebuilds, tests, packs one tarball, verifies the release source and
exact-source dogfood certification, smoke-tests the same tarball, and
publishes those bytes to npm.
