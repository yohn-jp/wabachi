# Wabachi 0.2.0

## Summary

0.2.0 establishes Architecture Documentation as a first-class Wabachi domain.
It introduces the versioned Architecture Canon, deterministic validation and
serialization, renderer-neutral documentation and view models, Structurizr
projection with explicit loss reporting, static HTML rendering, and production
CLI entry points for architecture validation and rendering.

The complete path is dogfooded by Wabachi's own checked-in architecture
declaration and certified against a real pinned Structurizr vNext release.

## Added

- Versioned, provider-neutral Architecture Canon with stable semantic identity.
- Canonical elements and containment, including actor support and
  projection-neutral display/technology/tag/property annotations.
- Typed relationships and interfaces.
- Responsibilities, authority, ownership, boundaries, and declarative
  architectural constraints, including complete-document enforcement of
  declared single-authority invariants.
- Ordered behavior flows plus runtime/deployment topology.
- Explicit repository source, symbol/export, and test mappings.
- Architecture decisions, rationale, external references, and supersession.
- Renderer-neutral structural, dynamic, and deployment view specifications
  with canonical roots, scopes, descriptions, and presentation hints.
- Complete-document validation, strict v1 decoding, deterministic canonical
  JSON serialization, and bounded diagnostics.
- Deterministic human-readable architecture documentation projection.
- Structurizr vNext projection with machine-readable projection-loss
  diagnostics.
- Static architecture site generation combining Wabachi documentation,
  workspace DSL, projection-loss reporting, and Structurizr diagram output.
- `wabachi architecture validate <file>`.
- `wabachi architecture render <file> --out <dir>`.
- Wabachi self-dogfood Architecture Canon and real Structurizr vNext
  certification.

## Changed

- The minimum supported Node.js version is now Node.js 24.
- The Structurizr process adapter uses the current vNext `version` and
  `export -format static` command surface.
- Release publication is gated by exact-source Wabachi architecture dogfood
  certification before npm Trusted Publishing.

## Breaking changes / migration

Node.js 22 is no longer supported. Upgrade to Node.js 24 or newer before
installing Wabachi 0.2.0.

No Architecture Canon compatibility promise existed before this release; the
new v1 Canon is the first complete architecture-document contract.

## Upgrade

```bash
npm install --global wabachi@0.2.0
wabachi --version
```

Expected output:

```text
0.2.0
```

## Release verification

Before creating the GitHub Release, the exact merge commit must have a
successful `Architecture dogfood certification` workflow run.

Publishing is triggered by GitHub Release `v0.2.0` and uses npm Trusted
Publishing through the repository's release-triggered publish workflow. The
workflow rebuilds, tests, packs one tarball, certifies the release source,
smoke-tests the exact tarball, and publishes those same bytes to npm.
