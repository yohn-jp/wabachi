# Wabachi 0.2.1

## Summary

0.2.1 makes Wabachi's existing repository-analysis and Architecture Canon surface substantially easier to discover and operate without changing the underlying analysis or Canon semantics.

The release introduces a canonical command contract, progressive help, bounded intent-oriented `wabachi skill` playbooks, a practical usage manual, and a bundled agent Skill/plugin projection in the npm package.

## Added

- Versioned canonical command contract for the supported Wabachi CLI surface.
- Progressive root, domain, and leaf help projected from that command contract.
- `wabachi skill` and `wabachi skill <scenario>` for bounded operational playbooks.
- Deterministic text and JSON Skill projections with an explicit 4096-byte output bound.
- Initial Skill scenarios for repository analysis, provider matrices, Architecture Canon validation/rendering, and the normal Architecture Documentation workflow.
- `docs/USAGE.md` with practical installation, analysis, matrix, Canon, Structurizr, artifact-retention, and recovery guidance.
- Bundled `skills/wabachi/SKILL.md` and Codex plugin manifest in the published npm package.
- Package verification that certifies those documentation/plugin assets are present after packing and isolated installation.

## Changed

- README now routes users to the practical manual, live progressive help, and `wabachi skill` instead of duplicating the command catalog.
- Architecture CLI usage strings now derive from the canonical command contract.
- The bundled plugin version follows the Wabachi package version.
- The MIT license identity is now the canonical `Copyright (c) 2026 yohn-jp`.
- README hero branding was refreshed during the 0.2.0 → 0.2.1 development interval.

## Compatibility

There are no intended breaking changes in 0.2.1.

Existing `run`, `matrix`, `architecture validate`, and `architecture render` execution semantics remain compatible with 0.2.0. Node.js 24 or newer remains required.

## Upgrade

```bash
npm install --global wabachi@0.2.1
wabachi --version
wabachi --help
wabachi skill
```

Expected version output:

```text
0.2.1
```

## Release verification

Before creating the GitHub Release, the exact release merge commit must have a successful `Architecture dogfood certification` workflow run.

Publishing is triggered by GitHub Release `v0.2.1` and uses npm Trusted Publishing through the repository's release-triggered publish workflow. The workflow rebuilds, tests, packs one tarball, verifies the release source and exact-source dogfood certification, smoke-tests the same tarball, and publishes those bytes to npm.
